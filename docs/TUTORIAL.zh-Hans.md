# MMM Community：逐步使用教程

[English](TUTORIAL.md) · [繁體中文](TUTORIAL.zh-Hant.md) · **简体中文**

本教程适用于 macOS 或 Linux 上的 **Community 测试版浏览器模式**。先完成完全本地的流程：不需要账号、API Key 或付费模型。AI 步骤可选；此测试版暂不支持原生 Windows。

## 1. 启动 MMM

安装 Node.js 24 或更新版本，然后运行：

```sh
git clone https://github.com/jacbus1/mmm-community.git
cd mmm-community
npm start
```

打开终端输出的**完整本地网址**，包括 `#session=...` 片段。服务器会自动选择可用端口。请勿分享这个网址：片段可用于访问本地会话。完成后在终端按 `Ctrl+C`。可以在欢迎界面或右上角选择语言。

![MMM Community 首页](screenshots/home.png)

## 2. 创建项目并保存笔记

1. 点击**创建第一个项目**或**新建项目**，输入名称，例如 `Community library concept`，再点击**创建项目**。来源文件／文件夹可留空；浏览器模式不能附加它们。
2. 在**对话**页保持**笔记**模式，输入简短需求，例如：“设计社区图书馆预约页，列出使用流程、手机布局和无障碍检查。”
3. 点击**保存笔记**。文字会显示在对话中并保存在本地，**不会调用 AI**。

![本地项目中的合成示例笔记](screenshots/project-workspace.png)

## 3. 不用 AI，完成一个本地任务

1. 在同一个**对话**输入区选择**本地任务**，写清楚交付内容和验收标准，例如：“草拟三步预约流程，检查键盘操作。”点击**创建本地任务**。
2. 打开**任务**页。任务会列在这里，**工作流程树**只显示已记录的工作。本地任务不会自行执行。
3. 自己完成工作后，在任务上点击**提交成果**，填入真实结果并提交。MMM 会保存成果，任务转为**等待验收**。
4. 点击**检查并批准**，打开成果，在**验收证据**中写明检查了什么，勾选确认，再点击**批准完成**。只有批准后任务才算完成。
5. 可以在**成果**页重看内容，在**活动**页查看操作记录。

如果还没有实际成果，保留任务即可；不要批准空白或想象中的交付内容。

## 4. 可选：连接 AI 服务

只有需要供应商回答任务时才进行这一步。供应商请求可能收费。

1. 打开**设置与服务**，在 **API 连接 · 任务执行**下展开 **＋ 连接服务**。
2. 选择供应商，填写你的账号当前可用的模型 ID，并按需输入 API 密钥。仅使用你信任的 API 端点。点击**保存服务设置**；保存不会提交任务。
3. 如需验证，在已保存的连接上点击**测试**并确认少量测试请求；它可能消耗额度或收费。

浏览器模式的供应商密钥仅保存在服务器内存中；服务器重启后需要重新输入。提交后密钥输入框会清空。**网站登录和手动 CLI 登录彼此独立**，两者都不能直接用于 Community 自动团队任务。

## 5. 运行单个 AI 任务

1. 回到项目的**对话**页，选择 **AI 任务**。
2. 选择已设置的 **AI 服务**，写明确且非敏感的需求，以及理想答案应该包含的内容。
3. 检查**内容分类**，确认文字没有密钥、个人信息或私人数据，再点击**提交 AI 任务**。只有这次明确提交才会将选定文字发送给供应商。
4. 在**任务**页查看状态，在**成果**页查看保存的回复。供应商失败或结果不完整时，任务不会自动获批。
5. 检查实际成果并填写验收证据后，才使用**检查并批准**。重试会重新发送请求，需要再次确认，也可能增加费用。

## 6. 可选：进行设计团队讨论

1. 按第 4 步至少连接一个兼容的 **API 服务**。同一个连接可分配给多个角色，无需多个供应商。
2. 打开项目的**团队**页，点击**使用设计团队**并确认创建草稿。它会建立协调者、UI/UX 设计师、工程师、审核者四个角色，**不会启动工作**。
3. 为**每个**角色选择 API 服务，设置 1–3 轮讨论，点击**保存团队**。也可以修改名称／角色，或自行建立 1–8 人团队。
4. 在**对话**页选择 **AI 任务**及**使用项目团队讨论**，输入非敏感需求。除内容确认外，还要单独同意将需求及代理回复分享给所选供应商，最后点击**提交 AI 任务**。
5. 在**任务 → 工作流程树**查看实际发生的轮次，在**成果**页查看结果。协调者汇总和代理回复只会在真正产生后显示。按第 5 步检查结果并以证据验收。

更多代理和轮次可能增加费用。这是文本协作；Community 版不会自动编辑文件、执行 shell 命令或控制供应商网站。

## 7. 保存工作与排除常见问题

- **备份：** 先停止 MMM，再将完整 Community 数据目录复制到自己的安全备份位置。各平台路径见[隐私与存储](../README.zh-Hans.md#隐私与存储)。项目数据在磁盘上未加密，请使用系统磁盘加密。
- **导出任务大纲：** 在**团队 → 项目工具**点击**导出 Markdown**。它只包含任务元数据，不包含笔记、供应商密钥、来源路径、完整成果，也不是完整备份。导入 MMM Markdown 提案需要先预览和确认，创建的是本地任务。
- **看不到 AI 服务：** 到**设置与服务**建立 API 连接。网站标签页或 CLI 登录不等于 API 连接。
- **任务等待验收：** 打开成果并填写验收证据；供应商有文字回复不代表任务自动完成。
- **本地 session 失效：** 使用当前 `npm start` 终端输出的完整网址重新打开。每次启动都会生成新片段。
- **浏览器的文件按钮不可用：** 文件／文件夹来源引用需要可选的桌面桥接；浏览器模式仍可使用项目、笔记和本地任务。

功能及限制详见[简体中文 README](../README.zh-Hans.md)。报告问题可使用 [GitHub Issues](https://github.com/jacbus1/mmm-community/issues)，请勿附上密钥、session 网址或私人项目数据。
