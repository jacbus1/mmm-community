# MMM Community：逐步使用教學

[English](TUTORIAL.md) · **繁體中文** · [简体中文](TUTORIAL.zh-Hans.md)

本教學適用於 macOS 或 Linux 上的 **Community 測試版瀏覽器模式**。先做完全本機的流程：不需要帳戶、API Key 或付費模型。AI 步驟可選；此測試版暫不支援原生 Windows。

## 1. 啟動 MMM

安裝 Node.js 24 或更新版本，然後執行：

```sh
git clone https://github.com/jacbus1/mmm-community.git
cd mmm-community
npm start
```

開啟終端機印出的**完整本機網址**，包括 `#session=...` 片段。伺服器會自選可用連接埠。請勿分享這個網址：片段可用來存取本機工作階段。完成後在終端機按 `Ctrl+C`。你可在歡迎畫面或右上角選擇語言。

![MMM Community 首頁](screenshots/home.png)

## 2. 建立專案並儲存筆記

1. 按 **建立第一個專案**或**新增專案**，輸入名稱，例如 `Community library concept`，再按**建立專案**。來源檔案／資料夾可留空；瀏覽器模式不能附加它們。
2. 在**對話**頁保持**筆記**模式，輸入簡短需求，例如：「設計社區圖書館預約頁，列出使用流程、手機版面與無障礙檢查。」
3. 按**儲存筆記**。文字會出現在對話內並保存在本機，**不會呼叫 AI**。

![本機專案中的合成示例筆記](screenshots/project-workspace.png)

## 3. 不用 AI，完成一個本機任務

1. 在同一個**對話**輸入區選擇**本機任務**，寫清楚交付物與驗收標準，例如：「草擬三步預約流程，檢查鍵盤操作。」按**建立本機任務**。
2. 開啟**任務**頁。任務會列在這裡，**工作流程樹**只展示已記錄的工作。本機任務不會自行執行。
3. 自己完成工作後，在任務上按**提交成果**，填入真實結果並提交。MMM 會儲存成果，任務轉為**等待驗收**。
4. 按**檢查並批准**，打開成果，在**驗收證據**填寫你檢查了甚麼，勾選確認，再按**批准完成**。只有批准後任務才算完成。
5. 你可在**成果**頁重看內容，在**活動**頁查看操作紀錄。

若還沒有實際成果，保留任務即可；不要批准空白或想像中的交付物。

## 4. 可選：連接 AI 服務

只有需要供應商回答任務時才做這一步。供應商請求可能收費。

1. 開啟**設定與服務**，在 **API 連接 · 任務執行**下展開 **＋ 連接服務**。
2. 選擇供應商、填寫你帳戶目前可用的模型 ID，並按需要輸入 API 密鑰。只使用你信任的 API 端點。按**儲存服務設定**；儲存不會提交任務。
3. 如要驗證，在已儲存的連接按**測試**並確認少量測試請求；它可能消耗額度或收費。

瀏覽器模式的供應商密鑰只保留在伺服器記憶體；伺服器重啟後要重新輸入。提交後金鑰輸入框會清空。**網站登入及手動 CLI 登入彼此獨立**，兩者都不能直接用於 Community 自動團隊任務。

## 5. 執行單一 AI 任務

1. 回到專案的**對話**頁，選擇 **AI 任務**。
2. 選擇已設定的 **AI 服務**，寫明確而非敏感的需求及理想答案應包含的內容。
3. 檢查**內容分類**，確認文字沒有密鑰、個資或私人資料，再按**提交 AI 任務**。只有這次明確提交才會把所選文字發給供應商。
4. 在**任務**頁看狀態，在**成果**頁看儲存的回應。供應商失敗或結果不完整時，任務不會自動獲批。
5. 檢查實際成果並填寫驗收證據後，才使用**檢查並批准**。重試會重新送出請求，需再次確認，亦可能增加費用。

## 6. 可選：進行設計團隊討論

1. 按第 4 步至少連接一個相容的 **API 服務**。同一連接可分配給多個角色，毋須多個供應商。
2. 開啟專案的**團隊**頁，按**使用設計團隊**並確認建立草稿。它會建立協調者、UI/UX 設計師、工程師、審核者四個角色，**不會啟動工作**。
3. 為**每個**角色選擇 API 服務，設定 1–3 輪討論，按**儲存團隊**。你也可以改名稱／角色，或自行建立 1–8 人團隊。
4. 在**對話**頁選擇 **AI 任務**及**使用專案團隊討論**，輸入非敏感需求。除了內容確認，還要另行同意把需求及代理回覆分享給所選供應商，最後按**提交 AI 任務**。
5. 在**任務 → 工作流程樹**查看實際已發生的輪次，在**成果**頁查看結果。協調者整合及代理回覆只會在真正產生後顯示。按第 5 步檢查結果並以證據驗收。

更多代理和輪次可能增加費用。這是文字協作；Community 版不會自動編輯檔案、執行 shell 指令或操控供應商網站。

![未設定服務的四角色設計團隊草稿](screenshots/design-team.png)

## 7. 保存工作與排除常見問題

- **備份：** 先停止 MMM，再把完整 Community 資料目錄複製到自己的安全備份位置。各平台路徑見[私隱與儲存](../README.zh-Hant.md#私隱與儲存)。專案資料在磁碟上並未加密，請使用系統磁碟加密。
- **匯出任務大綱：** 在**團隊 → 專案工具**按**匯出 Markdown**。它只含任務中繼資料，不包含筆記、供應商金鑰、來源路徑、完整成果，也不是完整備份。匯入 MMM Markdown 提案需先預覽和確認，建立的是本機任務。
- **看不到 AI 服務：** 到**設定與服務**建立 API 連接。網站分頁或 CLI 登入不等於 API 連接。
- **任務等待驗收：** 打開成果並填寫驗收證據；供應商有文字回覆不等於任務自動完成。
- **本機 session 失效：** 用目前 `npm start` 終端機印出的完整網址重新開啟。每次啟動都會有新片段。
- **瀏覽器的檔案按鈕不能用：** 檔案／資料夾來源參照需要可選的桌面橋接；瀏覽器模式仍可使用專案、筆記和本機任務。
